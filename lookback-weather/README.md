# 蓦然回首 · 实时天气与真实日照（Wallpaper Engine Web 壁纸）

在工坊壁纸 **3365960230《蓦然回首结尾动态时间变化》** 的画面基础上重写的 Web 壁纸：
**用你所在城市的真实太阳位置和当地实时天气驱动画面**，而不是跟随系统时钟。

原作的实现是「5 组按时钟切换的预渲染大图 + 18 分钟硬切淡化」（`engine.timeOfDay`）。
本作改成：

| 维度 | 原作 | 本作 |
|---|---|---|
| 昼夜切换 | 系统时钟小时（`START_HOUR`/`END_HOUR` 常量） | **太阳高度角 + 上午/下午**（连续权重，换时区/纬度/季节都对得上） |
| 太阳位置 | 无 | NOAA 算法本地计算，高度角 + 方位角 |
| 天气 | 无（SceneScript 沙箱不能联网） | open-meteo 实时：云量低/中/高、风速、降水概率、WMO code |
| 窗户朝向 | 无 | 8 方位 + 微调，直接决定有没有光柱、光柱朝哪偏、影子往哪落 |
| 建筑阴影 | 无（预渲染图自带死光影） | 2.5D 高度场投影，随太阳高度角/方位角实时变化 |
| 云 | 一条贴图 `frac()` 平移，只挂在 4 层（夜晚不飘） | 每层云量分别控制不透明度，风速驱动漂移速度，日夜都飘 |
| 雨 | 手动开关（且 `rainonoff1` 没在 project.json 声明，等于死的） | 降水概率 + WMO code 连续驱动，风速决定倾角 |
| 属性面板 | 8 个滑块，且标签与实际绑定错位 | 20+ 项，分组 + 条件显示 |

## 在哪预览

**A. 普通浏览器（最快，改完刷新就见效）**

双击 `tools/preview.cmd` —— 自动起本地服务器并打开：

```
http://127.0.0.1:8777/index.html?panel=1&hud=1
```

URL 参数（简写）：`panel=1` 开调参面板、`hud=1` 开 HUD、
`mode=manual&hour=17&win=270`、`cloud=90&rain=75&wind=45`、`wmo=95`、
`lat=39.9042&lon=116.4074&city=北京`。
浏览器里按 **P** 开关调参面板、**H** 开关 HUD。

**B. Wallpaper Engine（真实环境）**

把整个 `lookback-weather/` 文件夹复制到：

```
%USERPROFILE%\Documents\My Wallpaper\Wallpaper Engine\projects\
```

WE 菜单 → 浏览 → 本地壁纸 → 选 `lookback-weather`。
在 WE 属性面板里勾「调参面板」也会出现同样的面板。

## 数据来源（全部免费、无需 API Key）

| 用途 | 接口 |
|---|---|
| 天气 + 日出日落 | `api.open-meteo.com/v1/forecast`（`cloud_cover_low/mid/high`、`wind_speed_10m`、`precipitation_probability`、`snowfall`、`weather_code`、`is_day`） |

**太阳位置不依赖网络**，断网也有真实日出日落。

## 2.5D 太阳阴影（`js/sunshade.js`）

在 2D 建筑上画随时间变化的阴影，本质上需要一张**高度场**。好消息是：
`房屋*.png` 的 **alpha 通道本身就是干净的城市剪影**（黑=天空、白=建筑与窗棂），
所以高度场能自动从素材提取，换图不用重画。

```
alpha → 二值遮罩 → 形态学开运算（抹掉细窗棂，否则会投出假影子）
      → 找基线（向下扫描时「有→无」转换最多的那一行 = 建筑底边）
      → 每列屋顶 → 高度剖面 H(x) → 平滑
```

然后对每个像素：

```
hSelf = baseY − y                              // 自身高度
reach = maxH · |sin(rel)| / tan(仰角)           // 影子的屏幕长度
rise  = tan(仰角) / max(|sin(rel)|, 0.25)       // 每单位屏幕 x 射线上升多少
沿 −sign(sin rel) 方向行进，若 H(那边) > hSelf + u·rise → 进阴影
```

`rel = 太阳方位角 − 窗户法线`。**关键是 `|sin(rel)|` 不能只取符号**：

| rel | 场景 | 处理 |
|---|---|---|
| ≈0 | 太阳在楼后，逆光 | 横向投影≈0，影子落向镜头看不见 → 改成整体逆光压暗 + 天空辉光 |
| ≈±90 | 侧光 | 影子最长，完全展开 |
| ≈±180 | 太阳在身后 | 影子落向楼后，立面应该受光 → 不加投影阴影 |

叠加分两层，混合模式不同（混在一起会互相抵消）：

- **阴影层 `multiply`**：RGB 是衰减乘数，1 = 不变；阴影偏冷 + 楼缝 AO
- **受光层 `screen`**：太阳直射的暖色；只画在建筑遮罩内，所以窗框和天空不受影响

性能：一次全量重算约 250ms，所以**分帧摊销**——太阳一动就开新任务，
每帧只算 1/10 行（约 12ms），算完才整体贴上，期间继续用旧图，不会闪。

开关：调参面板「太阳阴影强度」，或属性面板 `sunShade`（0 = 关闭，回退到纯调色）。

## 图层顺序（踩过的坑）

```
天空云带 → 房间 → 太阳阴影 → 光柱 → 雨/飘落物 → 近景(人物/桌子) → 雾 → 文字
```

早先把光柱画在最上层，结果它横穿天花板、人物和桌子。光柱是**房间里的空气介质**，
必须压在远景之后、近景之前。太阳阴影同理，只影响窗外的楼，不能染到室内。


图层清单集中在 **`js/config.js` 的 `LB.LAYERS`**（外加 `LB.WINDOW` 窗户矩形）。
每层写明 `file / kind / slot / cx,cy / w,h / scale`，坐标沿用原壁纸的
虚拟画布 **5120×2592**（Wallpaper Engine 场景坐标 **+y 朝上**）。

```
kind: 'sky'   天空/云带 —— 横向无缝平移做视差，受云量控制
      'room'  室内+窗框+远景楼 —— 按太阳高度角交叉淡化
      'front' 近景 —— breathe 呼吸 / sway 摆动
```

换图只要改 `file` 和几何，代码不用动。

⚠️ **`assets/` 里的图是从工坊 3365960230（作者 被_整除）本地调试提取的，
公开发布到创意工坊之前必须换成你自己有授权的画。**
另外字体也换掉：原作用的 Anurati / Alcubierre 同样来自别人的工坊项，
本作暂时用系统等宽字体顶替。

## 已知的坑（都踩过了）

1. **WE 场景坐标 +y 朝上，Canvas +y 朝下。** 全局矩阵翻转 Y 之后，
   `drawImage` 会被一起镜像，**负高度并不能抵消**（实测 flip+(-h) 与 flip+(+h)
   结果完全一样，都是倒的）。正确做法是绘制前 `ctx.scale(1,-1)` 局部反变换，
   再用正高度绘制。
2. **粒子方向同理**：`d.y += v` 在 y 向上坐标系里是**往上飘**。
   雨/雪/叶子现在统一用速度矢量，`vy < 0` 才是下落；雨线拖尾画在速度反侧
   （`tail = p − v·k`），所以线和运动方向永远一致。
3. **风只有一个标量是不够的**：`wind_speed_10m` 必须配 `wind_direction_10m`
   （来向，0=北）。风实际往「来向+180°」吹，所以 `windX = −sin(dir)·speed`。
4. **太阳算法不能用 `getUTCHours()` 再减时区偏移**，等于把时区算两遍。
   本作直接用 UTC 绝对时刻算真太阳时，时区只参与显示。
5. **NOAA 方位角公式前面那个负号不能少**，少了会在正午算出 azimuth≈1°。
6. 高度场的坐标必须从**参考层自己的虚拟矩形**推导。早先拿 `LB.WINDOW` 去算，
   导致源图被纵向拉伸 13.6%、`baseY` 偏了 110 单位、叠加图整块错位。
7. **天空球 `depthWrite:false` 会让后面的东西画到天空前面**。
   那张远景雾化板就是这样把正午糊成一张白纸的，改成原生 `FogExp2` 才对。
8. `屋内.png` 的 alpha 正好是干净窗洞 —— 这是整套伪 2D 方案成立的前提。
